# Changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

The repository was recreated on 2026-04-28. Commit history before that date was
reconstructed afterwards from the existing code, so its dates are approximate.

## [Unreleased]

### Added
- Multi-module Maven project structure (core, ingest, match, server, cli)
- Unified domain model with Java 21 records (`SanctionedEntity`, `NameInfo`, `Address`, `Identifier`, `SanctionsProgram`)
- Enums with `displayName()` and `fromString()`: `EntityType`, `ListSource`, `NameType`, `NameStrength`, `ScriptType`, `IdentifierType`
- In-memory entity index (`InMemoryEntityIndex`) with thread-safe concurrent access
- `ListProvider` SPI for sanctions list fetchers
- OFAC SDN provider with StAX streaming XML parser and ETag-based delta detection
- Stub providers for EU Consolidated, UN Consolidated, and UK HMT lists
- `IngestionOrchestrator` for coordinated multi-source ingestion with reporting
- Jaro-Winkler string similarity algorithm (implemented from scratch)
- Exact match engine and fuzzy match engine
- Composite match engine with deduplication and best-score selection
- Spring Boot 3.3 REST API with screening, list management, health, and refresh endpoints
- RFC 7807 Problem Detail error responses via `@RestControllerAdvice`
- `@ConfigurationProperties` with Bean Validation
- Picocli CLI with `fetch`, `screen`, `stats`, and `export` commands
- Comprehensive test suite with JUnit 5, AssertJ, Mockito, and parameterized tests
- OFAC SDN test sample XML for offline testing
- Risk topics (`RiskTopic`: sanction, sanction-linked, export control, debarment, PEP, relative or close associate, crime, wanted, state-owned) and relations between entities (`Relation`, `RelationType`) on `SanctionedEntity`; entries from today's sanctions lists carry the `SANCTION` topic, and API responses and exports list each entity's `topics`
- Entity kinds `COMPANY`, `ORGANIZATION`, `CRYPTO_WALLET` and `SECURITY` beside `INDIVIDUAL`, `ENTITY`, `VESSEL` and `AIRCRAFT`; the generic `ENTITY` still covers lists that do not say which kind a legal entity is, and an `entityType` filter of `ENTITY` also returns companies and organisations. Relation type `POSITION_HELD` (a person and the position they hold, with dates), identifier types `ISIN` and `CRYPTO_ADDRESS`. The dashboard shows the new kinds once a list uses them
- Import and export in the open FollowTheMoney entity format: `sieve export --format ftm` writes one JSON object per line (entities, relations, sanctions and positions, with only the properties each schema defines), and `FtmReader` reads the format back into entities
- Provenance on every value: each name, date of birth, identifier, address, nationality, program, topic and relation of an entity records its source list, source URL, first seen and last seen (`SanctionedEntity.provenance`, `SourcedValue`, `Provenance`). Ingestion stamps every fetch and keeps a value's first seen time while the list keeps publishing it. The Spring API returns `provenance`, `firstSeen` and `lastSeen` on each entity, and the FollowTheMoney export carries `first_seen` and `last_seen`
- Name normalisation for matching: screening and cross-list matching compare names after romanising other scripts (Cyrillic by BGN/PCGN, Greek, Arabic, Hebrew, Chinese as pinyin, Korean and others, via ICU4J), folding accents and ligatures ("Müller", "Straße", "Łódź"), dropping apostrophes and splitting on other punctuation, and removing company legal forms (LLC, Ltd, PJSC, OOO, GmbH, S.A., Sp. z o.o. and others) from the start and end of organisation names, so "Путин" finds "Putin", "Rosneft PJSC" finds "Rosneft", and two companies no longer match because both are an LLC. A query drops legal forms unless it asks for a person, vessel or other non-organisation type. Names are still stored and shown as published
- PostgreSQL is the Spring server's system of record and is now required: each refresh is written to the database in one transaction before it reaches the in-memory screening index, delisted entities are copied to `entity_removal`, and the in-memory index is built from the database at startup, so stored entities and first seen times survive restarts (`PostgresEntityStore`, `PersistentEntityIndex`, Flyway V3 adds `first_seen`, `last_seen` and `entity_removal`). JPA is replaced by batched JDBC; the `sieve.index.type` setting and the `postgres` profile are gone. `docker compose` gains a `sieve-spring` service, and CI runs the database tests against PostgreSQL 16. The Spring server also starts without libpostal again, falling back to simple address normalisation as the Vert.x server does. Loading a large list into the in-memory index no longer slows down with its size (100,000 entities: 51 s before, 0.06 s now)
- US BIS Entity List (`US_BIS_ENTITY`, ids `bis-el-`) and Military End-User List (`US_BIS_MEU`, ids `bis-meu-`) as their own sources, split out of the Consolidated Screening List and tagged `EXPORT_CONTROL`; their licence requirement, licence policy and Federal Register notice are kept in remarks
- Argentina RePET (`AR_REPET`, ids `ar-person-` and `ar-entity-`): the Ministry of Justice terrorism registry, read from its people and entities JSON files
- India MHA (`IN_MHA`, ids `in-mha-`): individual terrorists designated under the Fourth Schedule of India's Unlawful Activities (Prevention) Act, read from the ministry's web page
- US FBI Wanted (`US_FBI_WANTED`, ids `fbi-`): people on open FBI wanted posters from the FBI's public API, tagged `WANTED`; missing-person, victim, kidnapping, unidentified-person, information-request and closed posters are left out
- EU Most Wanted (`EU_MOST_WANTED`, ids `eu-mw-`): fugitives EU member states publish through Europol's most wanted site, tagged `WANTED`, with the crime, requesting country and case state, plus date of birth and nationality from each poster page; solved cases are left out
- World Bank Debarred (`WB_DEBARRED`, ids `wb-`): firms and individuals the World Bank Group has debarred, tagged `DEBARMENT`, with address, grounds and ineligibility period; the Bank has no download, so the list is read from the API behind its debarred-firms page using the key that page publishes, and debarments that have ended are left out
- Wikidata PEPs now carry the relatives and close associates of every PEP found: the living people Wikidata links to a PEP as spouse, partner, child, parent, sibling, relative or business partner, tagged `RCA`, with a `FAMILY` or `ASSOCIATE` relation to the PEP, a program naming the link (`spouse of <name>`, `RCA tier <the PEP's tier>`) and the PEP's countries when no citizenship is recorded; a relative who holds an office is both `PEP` and `RCA`. Like PEP records, they are counted on the dashboard but never published; a live fetch found 7,548 of them next to 81,085 PEPs, 8 minutes all told
- Wikidata PEPs also cover the heads of government and state of each country's first-level regions (state governors, regional premiers and the like) as tier 2, found through each region's own office
- Wikidata PEPs also cover central bank governors, chiefs of defence and commanders-in-chief (tier 1), and deputy ministers, ambassadors, attorneys general and party leaders (tier 2)
- GLEIF State-Owned (`GLEIF_STATE_OWNED`, ids `lei-`): the companies whose direct or ultimate accounting parent in the LEI register is a government entity, tagged `STATE_OWNED`, with their LEI, registration number and BICs as identifiers, legal and headquarters addresses, other and transliterated names as aliases, and a remark per government parent; each government owner is an entity too, with an `OWNERSHIP` relation to every company it consolidates. Built from GLEIF's daily relationship file and its API; inactive companies are left out. A live fetch found 1,281 entities in a minute
- GLEIF Sanction-Linked (`GLEIF_SANCTION_LINKED`, ids `lei-linked-`): the companies whose accounts a party on the OFAC SDN or EU consolidated list consolidates, directly or through other companies, found by following the LEI register's relationship file down from the LEIs those lists state for their entries (the OFAC and EU 50% rules, with consolidation standing in for majority ownership); tagged `SANCTION_LINKED`, with a program per list (`OFAC SDN 50% rule`), a remark per link naming the parent, its list and programs, and a `LINKED` relation to the listed owner's own record or to the intermediate company. Companies listed themselves, by LEI or by name, and companies GLEIF marks inactive are left out. A live fetch found 71 companies under 183 listed parties (180 on OFAC SDN, 3 on the EU list) in 48 seconds, 31 of them spent downloading the EU list
- OFAC SDN digital currency addresses as crypto wallets: every address an entry lists under OFAC's "Digital Currency Address - XBT", "- ETH", "- USDT" and similar identifier types becomes a `CRYPTO_WALLET` entity of its own (ids `ofac-sdn-<uid>-wallet-<address>`), named by the address, with a `CRYPTO_ADDRESS` identifier per currency the address is listed under (the currency code as the identifier's remarks), the holder's programs and a remark naming the holder; the holder carries an `OWNERSHIP` relation to each of its wallets and each wallet a `LINKED` relation back, both with the role `holder`. The addresses stay on the holder's own record too, and the `ftm` export writes a wallet's currencies to `currency`. A live fetch made 1,052 wallets (528 Bitcoin, 261 Tron, 114 Ethereum, 86 Tether and 16 other currencies) from the list's 19,488 entries, within the 4 seconds the list takes to fetch and parse
- Wikidata PEPs (`WIKIDATA_PEP`, ids `wd-`): politically exposed persons from Wikidata, tagged `PEP`. Living holders of national offices (heads of state and government and ministers as tier 1, members of parliament and judges as tier 2) who are in office or left within five years, with each office, its country, tier and term in remarks; queried country by country to stay within the query service's limits
- The dashboard snapshot never writes PEP and RCA records or search-index entries; it counts them per list, in the history and in the overview's `byTopic` (entities per risk topic), and keeps them out of the headline totals, country map and top programs. Each list's row in `sources.json` also carries `published` (how many of its records were written) and `byTopic`
- The dashboard shows the counts: a politically-exposed tile on the overview, a risk-topics card under Composition, and a counts-only marker on lists whose records are not published
- The dashboard snapshot matches one entity's records across lists (`SimilarityDeduplicator`: names, identifiers, dates of birth) and writes the group's id as `g` on each search-index entry of an entity found on several lists; `overview.json` carries `dedup` (distinct entities, how many are on several lists), each list's row in `sources.json` carries `onOtherLists`, and the history keeps `distinctEntities` per day
- The dashboard folds a matched entity's records into one search result and lists them on the entity page as "Same entity on other lists"; the overview has a distinct-entities tile and each source's details say how many of its records other lists carry

### Changed
- `SimilarityDeduplicator` blocks on every token of every name instead of the first characters of the name as written, splits blocks on common prefixes by finer keys (prefix pairs, then the whole name), blocks entities again by birth year and by shared identifier so that variants of a common name still meet, compares each pair of tokens once per entity pair, and scores candidate pairs in parallel; a name match with neither an identifier nor a date of birth to corroborate it must now reach `DeduplicationConfig.uncorroboratedNameThreshold` (0.95), so similar names alone no longer merge; an identifier value shared by more than 50 entities (a gender or programme flag stored as an identifier) no longer counts as an identifier, and a name without a letter is not matched on
- OFAC SDN identifiers of type "Legal Entity Number" are typed `LEI` instead of `OTHER`
- OFAC SDN identifiers of type "Digital Currency Address - <currency>" are typed `CRYPTO_ADDRESS` instead of `OTHER`, with the currency code as remarks
- The Wikidata PEP fetch runs its queries four at a time and waits out the query service's throttling instead of giving up on a country, so the fetch took 7 minutes where the previous run took 23, with the same coverage; its log reports how long finding the office holders and describing them took
- The Wikidata PEP fetch retries a query whose connection dropped, and a country whose queries keep failing is tried once more in smaller batches before it is skipped; a slow spell at the query service had cost a run two countries
- Entity ids from OFAC SDN, UN, UK HMT and EU Consolidated now carry a source prefix (`ofac-sdn-`, `un-`, `uk-`, `eu-`), like every other source, so ids from different lists cannot collide
- A list refresh now replaces that source's entities, so entries the source has delisted are removed instead of staying until restart; refresh results report a `removedCount`, and an empty fetch keeps the previous entities and reports the source as failed
- Name caches and the n-gram index rebuild whenever the index content changes, not only when its size changes
- A match that covers only part of a listed name (a lone first or family name, or a one-word query against a longer name) is discounted by 0.75 in the exact, fuzzy and phonetic engines, so it no longer scores 1.0 and falls below the default 0.80 threshold
